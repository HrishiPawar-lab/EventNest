# Event API

The Event domain exposes public discovery and organizer event management. The public router is mounted at `/api/events`; the organizer router is mounted at `/api/organizer/events`. Public reads return only published events. Organizer operations use the verified Clerk session, active local EventNest account, and organizer role. Client-supplied `organizerId`, status, inventory counters, location, and cover image fields are rejected.

Responses use `{ "data": ... }`, with `{ "pagination": { "page", "limit", "total" } }` on lists. Errors use `{ "error": { "code", "message" } }`. Lists default to page 1 and limit 20, with a maximum limit of 100.

| Method  | Path                                     | Access    | Behavior                                                                                     |
| ------- | ---------------------------------------- | --------- | -------------------------------------------------------------------------------------------- |
| `GET`   | `/api/events`                            | Public    | Lists upcoming published events, ordered by start time.                                      |
| `GET`   | `/api/events/:eventId`                   | Public    | Reads a published event, including a past event. Draft and missing IDs return 404.           |
| `POST`  | `/api/organizer/events`                  | Organizer | Creates a draft at an owned venue.                                                           |
| `GET`   | `/api/organizer/events`                  | Organizer | Lists only the caller's events. Optional `status` filter.                                    |
| `GET`   | `/api/organizer/events/:eventId`         | Owner     | Reads one owned event.                                                                       |
| `PATCH` | `/api/organizer/events/:eventId`         | Owner     | Updates a draft only.                                                                        |
| `POST`  | `/api/organizer/events/:eventId/publish` | Owner     | Publishes an eligible draft. Empty JSON body only.                                           |
| `POST`  | `/api/organizer/events/:eventId/cancel`  | Owner     | Cancels a draft or published event with no ticket or payment activity. Empty JSON body only. |

Public list parameters are `page`, `limit`, `q` (literal name or description substring), `city`, `category`, `from`, `to`, `minPrice`, and `maxPrice`. `from` defaults to the current time; it and `to` are inclusive start-time bounds. Date filters must be ISO 8601 date-time strings with a timezone. City and category match whole values without case sensitivity. Prices are nonnegative. Search strings are capped at 100 characters, escaped before becoming regular expressions, and never accepted as MongoDB query objects. Public responses include `venueName` and `organizerName` from their referenced records (or `null` if a reference is missing), while `venueId` remains an ObjectId. Public responses omit `organizerId`, `imagePublicId`, and inventory counters. The current literal substring search may scan the collection; verify query plans and add an index or search service when data volume warrants it.

Create requires `venueId`, `name`, `startDate`, `endDate`, `maxAttendees`, and `ticketPrice`. Optional fields are `description` and `category`. PATCH accepts a nonempty subset of those fields. Dates must be ordered, capacity must be a positive integer, and price in INR must be nonnegative and represent whole paise (at most two meaningful decimal places). A free draft may have price `0`, but publishing requires a positive price. The category is free text until the approved category list is defined. Status starts as `draft` and cannot be changed through create or PATCH. The event location is copied from the selected venue. Venue reassignment is allowed for drafts and updates the copied location.

Publish requires a draft whose start time is still in the future, a nonempty category, a positive whole-paise ticket price, and an owned venue whose capacity is at least the event capacity. It rechecks the price so older drafts with unsupported fractional values cannot publish. It rechecks the venue inside the transaction. A published event cannot be edited by PATCH. Cancellation accepts only draft or published events. It rejects an event with nonzero sold or reserved counters, any pending or confirmed reservation, any ticket record, or any payment record. Blocking even failed payment attempts is deliberate while the event cancellation policy for provider orders and refunds remains undefined; this avoids a delayed provider notification becoming stranded. Expired pending holds must be marked expired and released by the reservation worker before cancellation. Transition endpoints accept no query parameters or state-changing request fields.

The create and update service runs in a MongoDB transaction and write-locks the selected venue by incrementing its Mongoose version field before saving the event. It verifies that the venue belongs to the organizer and that event capacity does not exceed venue capacity. Reducing event capacity below `ticketsSold + ticketsReserved` is rejected. The reservation service releases expired holds in a transaction, and its worker retries pending expirations. Venue writes and deletes participate in transactions using the same Venue document to preserve these checks under concurrency. MongoDB deployment must support transactions (such as an Atlas replica set).

Invalid bodies, query parameters, and IDs return `400 VALIDATION_ERROR`; foreign venues or events return `403 FORBIDDEN`; missing resources return `404 NOT_FOUND`; capacity conflicts return `409 CAPACITY_CONFLICT`; and edits to a nondraft event return `409 EVENT_NOT_DRAFT`. Transition errors use `409 INVALID_EVENT_STATE`, `PUBLISHING_REQUIREMENTS`, or `EVENT_HAS_ACTIVITY`. Unexpected database errors remain generic through the central error handler.

Publishing and cancellation use database transactions and organizer ownership checks. Reservation creation and [payment fulfillment with ticket issuance](payments.md) also write the Event document, so concurrent operations conflict or retry against current state. Cancellation rejects all existing payment and ticket records, including unfulfilled orders. Authenticated cover uploads are available through the [media API](media.md). Live Razorpay and Cloudinary operations, MongoDB query plans, and concurrent transaction behavior have not yet been verified.

Public event lists also accept `sort=date` (default, earliest first) or `sort=price` (lowest ticket price first). Sorting is applied before pagination.
