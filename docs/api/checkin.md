# Organizer QR check-in API

`POST /api/organizer/events/:eventId/check-ins` requires a valid Clerk session, an active email-verified EventNest organizer account, and ownership of the event. The JSON body is `{ "token": "<opaque QR token>" }`. A successful scan returns `200 { "data": { "ticketId", "status": "used", "usedAt" } }`.

The backend hashes the supplied token and conditionally write-locks an active QR credential and published event within a MongoDB transaction. Check-in opens two hours before event start and closes at scheduled event end. It then atomically changes the matching ticket from `valid` to `used`, recording the check-in time and organizer user ID. A second scan cannot succeed. Future credential revocation and event cancellation must update the same credential/event documents in transactions to preserve this coordination. The QR token is never logged or stored in plaintext. No client-side scanner result is trusted.

Missing or invalid sessions return `401 UNAUTHORIZED`; attendees and foreign organizers return `403 FORBIDDEN`; malformed event IDs or token bodies return `400 VALIDATION_ERROR`; a missing event returns `404 NOT_FOUND`; a used ticket returns `409 ALREADY_USED`; an event outside its check-in window or with a cancelled or completed status returns `409 EVENT_NOT_OPEN`; and invalid, revoked, missing-ticket, or wrong-event credentials return `422 INVALID_QR`. More than 120 scans per organizer per minute return `429 RATE_LIMITED`. The limiter is held in each API process. Unexpected failures return `500 INTERNAL_ERROR` without internal details. Only the owning organizer may check in attendees in v1; staff permissions remain deferred by the database architecture.
